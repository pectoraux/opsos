   594→- Decisions:
   595→  * The matching engine ships a TINY generic built-in predicate evaluator (eq/ne/gt/lt/gte/lte/in/and/or/not/attr-*/capability-has) so the kernel compiles and runs end-to-end. Protocol-specific predicates evaluate to a documented fallback (true for `include`/`exclude` so they're no-ops; true for `autoRejectPolicy` so it fails-safe; false for `autoAcceptPolicy` so it never short-circuits; false for `EscalationPolicy.condition` so unknown conditions never trigger). Protocols install richer evaluators via the extension system — the kernel NEVER interprets business-specific predicates.
   596→  * Unknown `Constraint` kinds default to SATISFIED (the kernel cannot interpret protocol-specific constraints).
   597→  * Reservation `confirm` mints the `commitmentId`; the CommitmentEngine's `create` consumes that exact id, so the lineage reservation → commitment is auditable.
   598→  * `coordinate-work` passes the same `now` to every engine call (the use-case is an atomic coordination act at a point in time). Tests / callers needing time-elapsed semantics call the engines individually with different `now` values.
   599→  * `weighted` queue discipline requires a caller-supplied seeded `RandomSource` for true weighted-random selection; absent that, the engine deterministically picks the heaviest entry (ties by insertion order) — the documented round-robin-within-weight-classes degenerate.
   600→  * Matching-tie tie-break is `resourceId` lexicographic ASC (the determinism anchor); queue-discipline ties (priority, deadline, weighted-fallback) are broken by `enqueuedAt` ASC.
